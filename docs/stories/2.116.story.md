## Story

**Como** responsavel pela continuidade operacional entre o PC principal e o notebook,
**quero** que os comandos de inicio e encerramento tratem Protheus e SommersStore como repositorios Git independentes,
**para que** o projeto canonico de investimentos e o painel administrativo sejam sincronizados, validados e publicados com politicas proprias, sem misturar stages, branches, commits, conflitos ou segredos.

## Acceptance Criteria

1. A configuracao declara separadamente `C:\AIOX\Workspace\Protheus`, branch `main`, prioridade 1, e `C:\AIOX\Workspace\SommersStore`, branch `migration/pc-new-20260907`, prioridade 2.
2. A sincronizacao de inicio executa fetch dos dois repositorios e gera resultado individual com identificador, raiz, branch esperada/atual e HEAD local/remoto.
3. O inicio so aplica fast-forward quando o repositorio esta limpo, sem stage e sem divergencia; workspace sujo, branch incorreta, conflito ou divergencia bloqueia apenas a aplicacao e nunca causa sobrescrita.
4. O encerramento classifica cada workspace separadamente, usando politica de privados/runtime/credenciais e allowlist compativel com cada projeto.
5. Antes de qualquer mutacao Git no encerramento, os dois repositorios passam por preflight completo: branch, stage vazio, classificacao, varredura de segredos, gates proprios, fetch e prova de que o remoto e ancestral do HEAD local.
6. Protheus executa seus gates `npm run lint`, `npm run typecheck` e `npm test`; SommersStore executa esses tres gates mais `npm run validate:structure` e `npm run validate:agents`.
7. Cada repositorio usa stage explicito por caminho, commit proprio, push normal para sua branch declarada e leitura remota posterior; ficam proibidos `git add -A`, `git add .`, force push e alteracao automatica de stash.
8. Um bloqueio em qualquer preflight impede commits e pushes dos dois repositorios naquela execucao, evitando publicacao parcial antes da validacao global.
9. O Protheus permanece em repositorio GitHub privado; a automacao registra a politica esperada e nao altera visibilidade, configuracao remota ou permissoes.
10. O Restic continua incluindo integralmente os workspaces Protheus e SommersStore, inclusive arquivos ignorados permitidos, e confirma snapshot local/nuvem identico sem excluir historico ou snapshots.
11. Firebase continua separado e considera somente artefatos publicaveis do SommersStore; o ensaio inicial usa `--no-shutdown --test-mode` e nunca executa deploy real.
12. Nenhum fluxo abre, fecha, configura ou altera MetaTrader, NinjaTrader, JForex, Profit ou qualquer plataforma; nenhum stash, snapshot ou historico e criado, aplicado, apagado ou limpo pela correcao Git.
13. Testes cobrem ordem de prioridade, branches esperadas, fetch/fast-forward independente, bloqueio dirty/divergente, classificacao por repositorio, gates proprios, preflight global, stage explicito e confirmacao dos dois HEADs remotos.
14. Um teste integral `--no-shutdown` produz relatorio dos dois repositorios e conclui Restic/espelho sem shutdown nem Firebase real.
